# 🚀 Ubuntu Hello v1.1.6 Release

Welcome to the **v1.1.6** release of **Ubuntu Hello**! This release adds a best-effort, safe self-abort mechanism for the compare process, plus packaging/CI dependency updates and hardening. **It does not fully resolve** the original report (face recognition continuing to run after Esc at a GNOME/GDM lock screen) — see below for exactly what was verified and what remains open.

---

## ✨ What's in v1.1.6

*   **🐛 New: `compare.py` self-aborts on a genuine session-idle transition**:
    *   With the shipped default `core.workaround = off`, nothing in the PAM module was ever told to cancel a running `compare` process. The only existing cancel path (`terminate_compare_group()` in `main.cc`) only fires when a concurrent password-watch thread wins the race, and that thread only exists when `workaround != off`.
    *   **Deliberately did not** widen the PAM-side password-watch gating to fix this. `AGENTS.md` has an explicit `[!CAUTION]` HARD RULE over that exact code, guarding against a worse prior incident: doing so previously broke GDM login outright — selecting a user on the account list immediately bounced back to the login screen.
    *   Added instead a mechanism that stays entirely inside `compare.py`'s own process: a daemon thread (`_watch_session_idle`) polls the current login1 session's `IdleHint` via `busctl` (absolute path, `/usr/bin/busctl` — this runs as root during PAM auth) roughly twice a second. It's **edge-triggered**: it requires an observed `false` reading before treating a later `true` as a cancel signal, so waking an already-idle lock screen (the normal case — `IdleHint` is only cleared on successful unlock) is never mistaken for a cancel. On a genuine `false → true` transition it sends the process `SIGTERM` — not a direct `cleanup()` call from the watcher thread, which would race the main thread's concurrent camera/GTK access — so cleanup runs through the existing main-thread signal handler exactly like an external cancel. `_session_idle_hint()` only accepts exactly `b true`/`b false` from `busctl`; anything else is treated as undetermined, never as `true`.
    *   Fails open by design: if `busctl`/logind are unavailable, or a given greeter/login-manager doesn't expose session idle state, the watcher simply stops after a few failed checks — the scan behaves exactly as before this release, with no new failure mode.
    *   New config: `core.abort_on_session_idle` (default `true`).
    *   **Fixed a race found in PR review**: `_session_idle_hint()`'s blocking `busctl` calls (up to a few seconds) could still be in flight when the main thread independently finished a successful/failed exit. A late `true` reading returned after that point could still send `SIGTERM`, re-enter the signal handler, and override the already-decided exit code with abort code `12` — silently corrupting a legitimate result. Both the signal handler and the watcher's pre-signal check now re-verify cleanup hasn't already run before acting, so a decided exit code can no longer be overridden. Covered by a new regression test simulating cleanup completing while the probe is still blocked.
*   **⚠️ Known limitation, confirmed by live testing — this does not fix Esc on GNOME/GDM**: after implementing the above, live D-Bus capture across a real Esc-at-lock-screen repro (both the system bus and the user session bus, full traffic, multiple repro rounds) showed `IdleHint` never transitions for that specific scenario on GNOME/GDM — pressing Esc only toggles GNOME Shell's internal password-prompt-vs-idle-clock sub-view, which exposes no external signal we could find (`logind IdleHint`, `xdg-desktop-portal Inhibit`'s `screensaver-active`, and `org.gnome.ScreenSaver.ActiveChanged` all stayed unchanged; `org.gnome.ScreenSaver.WakeUpScreen` and `Mutter.IdleMonitor` watches do fire, but also on ordinary interaction like typing a password, so using them would risk aborting a legitimate scan). **Net result: on GNOME/GDM this feature is currently a dormant safety net, not a working fix for the original report.** It's kept because it's harmless and may help on other desktop/login-manager combinations where `IdleHint` does reflect UI state. See `AGENTS.md` lifecycle notes for the full investigation.
*   **📦 Also in this release**: bumped the Flatpak runtime/SDK to `25.08`, and several pinned GitHub Actions (`upload-artifact`, `download-artifact`, `setup-buildx-action`, `setup-qemu-action`) to their current latest releases. CI hardening: explicit least-privilege `permissions: contents: read` on the `lint`/`coverage`/`compat` jobs in `check.yml` (previously relying on repository defaults), and exposing the GitHub Actions cache runtime variables (`crazy-max/ghaction-github-runtime`) that `buildx`'s `type=gha` cache backend needs but `setup-buildx-action` alone does not provide.
*   **🧪 Verified**: `busctl`'s `GetSessionByPID` / `get-property IdleHint` output format confirmed directly against a real login1 session on this machine, matching the parser exactly. Full unit coverage in `tests/test_compare_cleanup.py` for the idle-state probe (success, `false`, busctl failure/missing binary, malformed output, absolute-path invocation) and the edge-triggered watcher thread (SIGTERM on a real transition, no abort when already idle at start, gives up after repeated failures, never raises on unexpected errors). Full test suite passes.

## 📥 Installation

Download assets from the [GitHub Release](https://github.com/ventura8/ubuntu-hello/releases/tag/v1.1.6) page. Verify against `SHA256SUMS` before installing.

### Method 1: Quick Install (from release tag)
Download and review [`install.sh`](https://github.com/ventura8/ubuntu-hello/blob/v1.1.6/install.sh) from the **v1.1.6** tag, then run `bash install.sh` locally.

### Method 2: PPA (Ubuntu / Linux Mint)
```bash
sudo add-apt-repository ppa:ventura8/ubuntu-hello
sudo apt update
sudo apt install ubuntu-hello
```

### Method 3: Debian `.deb` (amd64 + arm64)
```bash
sudo apt install ./ubuntu-hello_1.1.6-1ppa1_$(dpkg --print-architecture).deb ./ubuntu-hello-gtk_1.1.6-1ppa1_$(dpkg --print-architecture).deb
```

### Method 4: Fedora RPM (amd64 + arm64)
```bash
sudo dnf install ./ubuntu-hello-1.1.6-1.fc44.$(uname -m).rpm ./ubuntu-hello-gtk-1.1.6-1.fc44.$(uname -m).rpm
```

### Method 5: openSUSE RPM (amd64 + arm64)
```bash
sudo zypper install ./ubuntu-hello-1.1.6-1.lp160.$(uname -m).rpm ./ubuntu-hello-gtk-1.1.6-1.lp160.$(uname -m).rpm
```

### Method 6: Arch Linux (amd64 only)
```bash
sudo pacman -U ubuntu-hello-1.1.6-1-x86_64.pkg.tar.zst ubuntu-hello-gtk-1.1.6-1-x86_64.pkg.tar.zst
```

### Method 7: Snap (classic, amd64 only)
```bash
sudo snap install --dangerous --classic ubuntu-hello_1.1.6_amd64.snap
sudo snap run ubuntu-hello.host-install
```

### Method 8: AppImage (installer, amd64 + arm64)
```bash
chmod +x Ubuntu-Hello-1.1.6-$(uname -m).AppImage
./Ubuntu-Hello-1.1.6-$(uname -m).AppImage --install
```

### Method 9: Flatpak (installer, amd64 only)
```bash
flatpak install --user ./com.github.ventura8.UbuntuHello-1.1.6-x86_64.flatpak && \
    flatpak run --command=ubuntu-hello-host-install com.github.ventura8.UbuntuHello
```
Approve the polkit prompt on the host-install step to install PAM and system files.

## 📋 Changelog (v1.1.6)

*   **Release**: Version **`1.1.6`** / **`v1.1.6`** from repo-root **`VERSION`**; `debian/changelog` top entry added.
*   **Feature (best-effort, does not fix Esc on GNOME/GDM)**: `compare.py` now sends itself `SIGTERM` on an observed `false → true` `IdleHint` transition (edge-triggered, not on an already-idle session at scan start), using an absolute `/usr/bin/busctl` path since this runs as root during PAM auth. `_session_idle_hint()` accepts only exact `b true`/`b false` from `busctl`, returning "undetermined" otherwise. New config: `core.abort_on_session_idle` (default `true`). **Live D-Bus testing confirmed `IdleHint` never transitions for Esc-at-GNOME-lock-screen**, so this does not resolve the originally reported symptom there — see the "Known limitation" section above.
*   **Fix (packaging/CI)**: bumped the Flatpak runtime/SDK to `25.08` and several pinned GitHub Actions to their current latest releases; fixed the Flatpak install command re-running the privileged host-install a second time instead of doing nothing extra.
*   **Fix (CI security)**: added explicit least-privilege `permissions: contents: read` to the `lint`/`coverage`/`compat` jobs, and exposed the GitHub Actions cache runtime variables `buildx`'s `type=gha` cache backend needs (`crazy-max/ghaction-github-runtime`) — without them, `--cache-to/from type=gha` in `scripts/ci-docker.sh` had no working cache backend.
*   **Fix (PR review)**: fixed a real thread-safety bug in the idle watcher's closure/lock handling, and hardened `_session_idle_hint()`'s `busctl` output parsing to reject malformed output instead of guessing. Fixed a further race where a late `busctl` reading returned after a concurrent successful/failed exit had already run could override the decided exit code with abort code `12`; the signal handler and watcher now both re-verify cleanup hasn't already run before acting.
*   **Docs**: documented the session-idle self-abort mechanism, its edge-triggered design, cross-thread signal handling, and — critically — its confirmed non-effectiveness for Esc-at-GNOME-lock, in `AGENTS.md` lifecycle notes, `docs/architecture/README.md`, `docs/INSTRUCTIONS.md`, and the `pam-verifier` skill, alongside the existing HARD RULE it deliberately does not touch.
*   **Tests**: added `tests/test_compare_cleanup.py` coverage for `_session_idle_hint()` (busctl success/failure/missing-binary/malformed output) and `_watch_session_idle()` (SIGTERM on a real transition, no abort when already idle at start, gives up after repeated failures, never raises); full test suite (545 tests) passes.
