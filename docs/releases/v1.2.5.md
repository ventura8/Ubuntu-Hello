# 🚀 Ubuntu Hello v1.2.5 Release

Welcome to the **v1.2.5** release of **Ubuntu Hello**! This is a **security release**: it fixes a local privilege escalation in the keyring/KWallet unlocking path. Anyone with keyring unlocking enabled should upgrade.

---

## ✨ What's in v1.2.5

*   **🔒 Security fix: root code execution through the keyring helpers.** When keyring/KWallet unlocking was enabled, the PAM module started two root helpers through `popen()`: the TPM unseal steps after a face match, and `ubuntu-hello keyring enable` from `pam_sm_setcred`. That runs `/bin/sh` as uid 0 with the **calling user's environment**. Because the module first switches the real uid to 0, the loader honours `LD_PRELOAD` and Python honours `PYTHONPATH`. A local user with keyring unlocking enabled could run `LD_PRELOAD=/tmp/evil.so su $USER`, authenticate with their own password or face, and run code as root without any sudo rights.
    *   Every root helper now starts through one function, `run_root_helper()`. It uses `posix_spawn` with an absolute path and a fixed argument list, with **no shell**, and passes only the scrubbed environment `compare.py` already used: a fixed `PATH` plus checked locale variables.
    *   The TPM unseal is now three direct runs of `/usr/bin/tpm2_createprimary`, `tpm2_load` and `tpm2_unseal`. The temporary context files are removed with `unlink()`.
    *   Sealing the keyring password at login runs `python3 -E -s cli.py keyring enable -U <user>` directly, with the password on stdin, instead of the `/bin/sh` `ubuntu-hello` wrapper. The username no longer passes through a shell string.
*   **🧪 Tests.** `pam-main` now checks that `LD_PRELOAD` and `PYTHONPATH` set in the parent arrive empty in a root helper. It also runs the TPM unseal chain against fake `tpm2_*` tools, checking each step's arguments, failures and context-file cleanup, and runs `keyring enable` against a fake CLI. The keyring paths of `try_set_keyring_authtok` and setcred's handling of the helper's result are covered too.

**Upgrade if you use keyring/KWallet unlocking.** Nothing changes in how face login or keyring unlocking work: no new config keys and no new or changed translatable strings.

| **MATE** | Yes | Yes | GNOME Keyring when present |

The booted-OS tier runs on `ubuntu`, `fedora` and `arch` for same-repository release pull requests (`feature/v*`) and on demand.

## 📥 Installation

Download assets from the [GitHub Release](https://github.com/ventura8/ubuntu-hello/releases/tag/v1.2.5) page. Verify against `SHA256SUMS` before installing. Download this release's assets into an empty/clean directory before running these commands — the wildcards below match by filename pattern, and leftover assets from another version in the same directory can make a package manager see multiple matches (or, for the AppImage command, pass a second matched file as a stray argument).

### Method 1: Quick Install (from release tag)
Download and review [`install.sh`](https://github.com/ventura8/ubuntu-hello/blob/v1.2.5/install.sh) from the **v1.2.5** tag, then run `bash install.sh` locally.

### Method 2: PPA (Ubuntu / Linux Mint)
```bash
sudo add-apt-repository ppa:ventura8/ubuntu-hello
sudo apt update
sudo apt install ubuntu-hello
```
Builds for Ubuntu **22.04 (jammy)**, 24.04 (noble) and 26.04 (resolute), and derivatives on them (Linux Mint 21 / 22). **On 22.04, use the PPA**: the `.deb` Release assets below are built on 26.04 and do not install there.

### Method 3: Debian `.deb` (amd64 + arm64)
```bash
sudo apt install ./ubuntu-hello_*_$(dpkg --print-architecture).deb ./ubuntu-hello-gtk_*_$(dpkg --print-architecture).deb
```

### Method 4: Fedora RPM (amd64 + arm64)
```bash
sudo dnf install ./ubuntu-hello-[0-9]*fc44*.$(uname -m).rpm ./ubuntu-hello-gtk-*fc44*.$(uname -m).rpm
```

### Method 5: openSUSE RPM (amd64 + arm64)
```bash
sudo zypper install ./ubuntu-hello-[0-9]*lp160*.$(uname -m).rpm ./ubuntu-hello-gtk-*lp160*.$(uname -m).rpm
```

### Method 6: Arch Linux (amd64 only)
```bash
sudo pacman -U ./ubuntu-hello-[0-9]*.pkg.tar.zst ./ubuntu-hello-gtk-*.pkg.tar.zst
```

### Method 7: Snap (classic, amd64 only)
```bash
sudo snap install --dangerous --classic ubuntu-hello_*_amd64.snap
sudo snap run ubuntu-hello.host-install
```

### Method 8: AppImage (installer, amd64 + arm64)
```bash
chmod +x Ubuntu-Hello-*-$(uname -m).AppImage
./Ubuntu-Hello-*-$(uname -m).AppImage --install
```

### Method 9: Flatpak (installer, amd64 only)
```bash
flatpak install --user ./com.github.ventura8.UbuntuHello-*.flatpak && \
    flatpak run --command=ubuntu-hello-host-install com.github.ventura8.UbuntuHello
```
Approve the polkit prompt on the host-install step to install PAM and system files.

## 📋 Changelog (v1.2.5)

*   **Version:** `VERSION` is **1.2.5**.
*   **PAM (`ubuntu-hello/src/pam/main.cc`):** `popen_as_root` replaced by `run_root_helper()` (`posix_spawn`, no shell, `helper_environment()`); new `unseal_tpm_password()`, `cache_keyring_password()` and `report_keyring_cache()`; `try_set_keyring_authtok()` takes its config and tool directories as parameters, defaulting to `/etc/ubuntu-hello` and `/usr/bin`.
*   **Build:** new `CLI_SCRIPT_PATH` in `paths.hh.in`, set from `src/meson.build`.
*   **Tests:** `tests/pam_main_test.cc` covers environment scrubbing, the TPM unseal chain, `keyring enable` and the keyring PAM paths.
*   **Docs:** `docs/SECURITY.md` §2.1, §2.3 and the threat table describe the `posix_spawn` root-helper path.
