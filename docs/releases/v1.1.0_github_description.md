# Ubuntu Hello v1.1.0 - Multi-DE Compatibility, Face Skip, AES Keyring & Split CI

This release expands **additional desktop compatibility** across **GNOME, KDE Plasma, XFCE, Cinnamon, MATE, Budgie, and LXQt**, hardens the PAM authentication lifecycle for greeters, adds software AES-256-GCM (`UH1:`) keyring support with automatic login-wallet unlock via `PAM_AUTHTOK` (**GNOME Keyring and KWallet**), and rebuilds CI into fail-fast lint / coverage / **parallel per-DE compat** stages with all Docker assets under `docker/`.

---

## 🖥️ Additional Desktop Compatibility (ALL supported DEs)

Face authentication via PAM (`common-auth`) remains **desktop-agnostic** and works with **GDM, SDDM, LightDM**, and similar display managers. This release documents and CI-gates **every** supported desktop:

| Desktop | Face auth | Theme follow | Session wallet auto-unlock |
|---------|-----------|--------------|----------------------------|
| **GNOME / Ubuntu** | Yes | Yes (`theme_detect.py`) | GNOME Keyring (`pam_gnome_keyring`) |
| **KDE Plasma** | Yes | Yes | **KWallet** (`pam_kwallet5` / `libpam-kwallet5`) |
| **XFCE** | Yes | Yes | GNOME Keyring when present |
| **Cinnamon** | Yes | Yes | GNOME Keyring when present |
| **MATE** | Yes | Yes | GNOME Keyring when present |
| **Budgie** | Yes | Yes | GNOME Keyring when present |
| **LXQt** | Yes (best-effort) | Yes | GNOME Keyring when present |

*   **Theme**: shared dark/light probes in `theme_detect.py` for all seven DEs (settings + auth overlay).
*   **Wallet UX**: `wallet_backend.py` labels `gnome-keyring` / `kwallet` / `none` — same `UH1:` / TPM sealed blob + `PAM_AUTHTOK` path (no second KWallet format).
*   **CI compat matrix** (each DE has its **own** Dockerfile + image; all run **in parallel**):
    *   `baseline`, `gnome`, `kde`, `xfce`, `cinnamon`, `mate`, `budgie`, `lxqt`

## ⏭️ Greeter Face-Skip After Failure

*   **Skip camera on the next greeter attempt**:
    *   On greeter/login PAM services (`gdm-password`, `lightdm*`, `sddm*`, `login`, `*screensaver*`), a completed non-zero compare exit sets `/run/ubuntu-hello/face-skip/<user>`.
    *   The next `identify()` returns `PAM_AUTHINFO_UNAVAIL` until face success or `pam_sm_setcred` clears the marker.
    *   Config: `core.skip_face_after_failure` (default on). Not applied to `sudo` / polkit.

## 🔐 AES-GCM Keyring (`UH1:`) & Session Wallets

*   **Software sealed blobs**:
    *   `UH1:` AES-256-GCM format in PAM (`aes_gcm_uh1.*`) and Python (`keyring_crypto.py`), with CLI/GTK enablement flows.
*   **Downstream unlock**:
    *   After a successful face match, PAM sets `PAM_AUTHTOK` for `pam_gnome_keyring` **and** `pam_kwallet5`.

## 🧹 Auth Lifecycle Hardening

*   Compare runs in a dedicated process group; password-wins-first cancel sends `SIGTERM` to the group, then `SIGKILL` after a grace period.
*   `compare.py` SIGTERM/SIGINT handlers release the camera, terminate/wait GTK, and exit `12` (avoid relying on `atexit` for SIGTERM).

## 🧪 Split CI Gate (Ubuntu 26.04)

*   **Stages**: `lint` → `coverage` → parallel **compat** DE cells (`baseline` + **gnome, kde, xfce, cinnamon, mate, budgie, lxqt**).
*   Dockerfiles under `docker/` (`Dockerfile.ci.lint`, `Dockerfile.ci.coverage`, `Dockerfile.ci.<de>`, `Dockerfile.ppa`).
*   Local `./scripts/ci-pipeline.sh` fail-fast between stages; GHA lint + coverage parallel, compat `needs` both; BuildKit cache via `UH_CI_DOCKER_CACHE`.
