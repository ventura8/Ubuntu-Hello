# 🚀 Ubuntu Hello v1.1.4 Release

Welcome to the **v1.1.4** release of **Ubuntu Hello**! This release adds **ARM64 Release artifacts**: `.deb`, Fedora RPM, openSUSE RPM, and AppImage now build and install-test for both **amd64** and **arm64**, each verified with the same live install → upgrade → remove → reinstall E2E cycle used for amd64. Arch, Snap, and Flatpak stay amd64-only for now, each for a concrete, documented reason.

---

## ✨ Key Enhancements in v1.1.4

*   **🦾 ARM64 Release artifacts**:
    *   [`.github/workflows/release.yml`](../../.github/workflows/release.yml): `build-deb`, `build-rpm-fedora`, `build-rpm-opensuse`, and `build-appimage` now run a matrix over `amd64` and `arm64`. arm64 legs use `docker/setup-qemu-action` + `docker build/run --platform linux/arm64`.
    *   Each arch runs `packaging-smoke-verify.sh` and `packaging-e2e-install.sh` (full install → upgrade → remove → reinstall) against its own image before upload — a bad arm64 build or a package that can't actually install fails the release job before any GitHub Release is cut.
*   **🐛 AppImage arm64 "Exec format error" fix**:
    *   Type-2 AppImages encode an `"AI\x02"` signature into the ELF `e_ident` ABI-version padding bytes. The standard `qemu-user-static` binfmt_misc registration requires an exact match on that byte, so the kernel refuses to hand an AppImage to QEMU under cross-arch emulation.
    *   `uh_appimage_squashfs_offset()` in [`scripts/release-common.sh`](../../scripts/release-common.sh) parses the ELF header directly to find the appended squashfs offset, then `unsquashfs` extracts it — no execution needed on the primary path. Used both to extract `appimagetool` itself in [`docker/Dockerfile.release`](../../docker/Dockerfile.release) and to extract our own built output AppImage in `packaging-e2e-install.sh`, which still falls back to executing the AppImage directly (`--appimage-extract`) if `unsquashfs` or offset detection is unavailable.
*   **🚫 What stays amd64-only, and why**:
    *   **Arch**: the official `archlinux` Docker image has no arm64 manifest.
    *   **Snap**: deferred — its build needs a privileged systemd+snapd container, unreliable under QEMU emulation.
    *   **Flatpak**: `flatpak-builder` always sandboxes builds with `bwrap`, which requires Linux user namespaces; `unshare --user` fails under QEMU user-mode emulation.
*   **🧹 Packaging script hardening**:
    *   RPM and AppImage artifact selection in `packaging-e2e-install.sh` now matches the running cell's own architecture instead of a bare wildcard + `head -n1`.
    *   `debian/rules`' `dh_clean` override now targets the exact `obj-$(DEB_HOST_GNU_TYPE)` build directory for the current architecture, instead of a broad glob.
    *   Release verify steps in `release.yml` run each script as a direct Docker command argument instead of a `bash -c` string.
*   **📚 Docs / agents**:
    *   [`.agents/skills/release-packaging/SKILL.md`](../../.agents/skills/release-packaging/SKILL.md) documents the arm64 coverage, the AppImage gotcha, and a mandatory amend-current-commit workflow with explicit pathspec staging (never `git add -A`) plus a staged-diff sanity check before amending.
    *   [`docs/INSTRUCTIONS.md`](../INSTRUCTIONS.md) and `AGENTS.md` updated so install instructions and packaging descriptions no longer imply amd64/x86_64-only asset names for the formats that now also ship arm64.

## 📥 Installation

Download assets from the [GitHub Release](https://github.com/ventura8/ubuntu-hello/releases/tag/v1.1.4) page. Verify against `SHA256SUMS` before installing.

### Method 1: Quick Install (from release tag)
Download and review [`install.sh`](https://github.com/ventura8/ubuntu-hello/blob/v1.1.4/install.sh) from the **v1.1.4** tag, then run `bash install.sh` locally.

### Method 2: PPA (Ubuntu / Linux Mint)
```bash
sudo add-apt-repository ppa:ventura8/ubuntu-hello
sudo apt update
sudo apt install ubuntu-hello
```

### Method 3: Debian `.deb` (amd64 + arm64)
```bash
sudo apt install ./ubuntu-hello_1.1.4-1ppa1_$(dpkg --print-architecture).deb ./ubuntu-hello-gtk_1.1.4-1ppa1_$(dpkg --print-architecture).deb
```

### Method 4: Fedora RPM (amd64 + arm64)
```bash
sudo dnf install ./ubuntu-hello-1.1.4-1.fc44.$(uname -m).rpm ./ubuntu-hello-gtk-1.1.4-1.fc44.$(uname -m).rpm
```

### Method 5: openSUSE RPM (amd64 + arm64)
```bash
sudo zypper install ./ubuntu-hello-1.1.4-1.lp160.$(uname -m).rpm ./ubuntu-hello-gtk-1.1.4-1.lp160.$(uname -m).rpm
```

### Method 6: Arch Linux (amd64 only)
```bash
sudo pacman -U ubuntu-hello-1.1.4-1-x86_64.pkg.tar.zst ubuntu-hello-gtk-1.1.4-1-x86_64.pkg.tar.zst
```

### Method 7: Snap (classic, amd64 only)
```bash
sudo snap install --dangerous --classic ubuntu-hello_1.1.4_amd64.snap
sudo snap run ubuntu-hello.host-install
```

### Method 8: AppImage (installer, amd64 + arm64)
```bash
chmod +x Ubuntu-Hello-1.1.4-$(uname -m).AppImage
./Ubuntu-Hello-1.1.4-$(uname -m).AppImage --install
```

### Method 9: Flatpak (installer, amd64 only)
```bash
flatpak install --user ./com.github.ventura8.UbuntuHello-1.1.4-x86_64.flatpak && \
    flatpak run --command=ubuntu-hello-host-install com.github.ventura8.UbuntuHello && \
    flatpak run com.github.ventura8.UbuntuHello
```
Approve the polkit prompt on the host-install step to install PAM and system files.

## 📋 Changelog (v1.1.4)

*   **Release**: Version **`1.1.4`** / **`v1.1.4`** from repo-root **`VERSION`**; `debian/changelog` top entry added.
*   **ARM64**: `release.yml` matrix (amd64 + arm64) for deb, Fedora RPM, openSUSE RPM, AppImage, each with per-arch smoke-verify + E2E install test.
*   **Fix**: AppImage arm64 "Exec format error" under QEMU — ELF-header-based squashfs offset + `unsquashfs`, never executing the wrapped AppImage.
*   **Hardening**: architecture-exact RPM/AppImage artifact selection; `debian/rules` cleans only the current arch's build dir; release verify steps use direct Docker args instead of `bash -c` strings; `docker/setup-qemu-action` and its underlying `tonistiigi/binfmt` image pinned to explicit versions.
*   **Docs / agents**: `release-packaging` skill (arm64 coverage, AppImage gotcha, amend-with-explicit-pathspec workflow), `AGENTS.md`, `docs/INSTRUCTIONS.md`.
