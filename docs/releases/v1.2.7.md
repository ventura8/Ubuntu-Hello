# 🚀 Ubuntu Hello v1.2.7 Release

Welcome to the **v1.2.7** release of **Ubuntu Hello**! This is a reliability release: login can no longer hang on a stuck TPM or keyring helper when keyring/KWallet unlocking is enabled.

---

## ✨ What's in v1.2.7

*   **⏱️ Login can no longer hang on a stuck keyring helper.** When keyring/KWallet unlocking is enabled, the PAM module runs root helpers: the `tpm2_*` steps that unseal the keyring password after a face match, and `keyring enable`, which caches the password at login. It waited for them with no time limit, so a hung TPM device or resource manager froze the login. Each helper now has **30 seconds**. It runs in its own process group, and if it is still running at the deadline the whole group is killed. Login then carries on without the keyring step: face auth is unaffected, and the keyring is just not unlocked or the password not cached that time.
*   **🧪 Tests.** `pam-main` covers a helper that never exits, one that prints and then hangs (its partial output is kept), output held open by a background child, and a slow helper inside the limit.

No new config keys and no new or changed translatable strings.

## 🖥️ Desktop / Greeter / Wallet Compatibility

Face auth via PAM (`common-auth`; `system-auth` via authselect on Fedora; hand-wired on Arch) remains desktop-agnostic with **GDM, SDDM, LightDM**:

| Desktop | Face auth | Theme follow | Session wallet auto-unlock |
|---------|-----------|--------------|----------------------------|
| **GNOME / Ubuntu** | Yes | Yes | GNOME Keyring (`pam_gnome_keyring`) |
| **KDE Plasma** | Yes | Yes | **KWallet** (`pam_kwallet5`) |
| **XFCE** | Yes | Yes | GNOME Keyring when present |
| **Cinnamon** | Yes | Yes | GNOME Keyring when present |
| **MATE** | Yes | Yes | GNOME Keyring when present |
| **Budgie** | Yes | Yes | GNOME Keyring when present |
| **LXQt** | Yes | Yes | GNOME Keyring when present |

CI compat cells (parallel): `baseline`, `gnome`, `kde`, `xfce`, `cinnamon`, `mate`, `budgie`, `lxqt` on Ubuntu 26.04, and `jammy` on Ubuntu 22.04 (build, unit tests, Settings E2E and the PAM module's C++ tests on meson 0.61, GTK 4.6, PyGObject 3.42, Python 3.10). The booted-OS tier runs on `ubuntu`, `fedora` and `arch` for same-repository release pull requests (`feature/v*`) and on demand.

## 📥 Installation

Download assets from the [GitHub Release](https://github.com/ventura8/ubuntu-hello/releases/tag/v1.2.7) page. Verify against `SHA256SUMS` before installing. Download this release's assets into an empty/clean directory before running these commands — the wildcards below match by filename pattern, and leftover assets from another version in the same directory can make a package manager see multiple matches (or, for the AppImage command, pass a second matched file as a stray argument).

### Method 1: Quick Install (from release tag)
Download and review [`install.sh`](https://github.com/ventura8/ubuntu-hello/blob/v1.2.7/install.sh) from the **v1.2.7** tag, then run `bash install.sh` locally.

### Method 2: PPA (Ubuntu / Linux Mint)
```bash
sudo add-apt-repository ppa:ventura8/ubuntu-hello
sudo apt update
sudo apt install ubuntu-hello
```
Builds for Ubuntu **22.04 (jammy)**, 24.04 (noble) and 26.04 (resolute), and derivatives on them (Linux Mint 21 / 22). **On 22.04, use the PPA**: the `.deb` Release assets below are built on 26.04 and do not install there.

### Method 3: Debian `.deb` (amd64 + arm64)
```bash
sudo apt install ./ubuntu-hello_*_$(dpkg --print-architecture).deb ./ubuntu-hello-gtk_*_$(dpkg --print-architecture).deb
```

### Method 4: Fedora RPM (amd64 + arm64)
```bash
sudo dnf install ./ubuntu-hello-[0-9]*fc44*.$(uname -m).rpm ./ubuntu-hello-gtk-*fc44*.$(uname -m).rpm
```

### Method 5: openSUSE RPM (amd64 + arm64)
```bash
sudo zypper install ./ubuntu-hello-[0-9]*lp160*.$(uname -m).rpm ./ubuntu-hello-gtk-*lp160*.$(uname -m).rpm
```

### Method 6: Arch Linux (amd64 only)
```bash
sudo pacman -U ./ubuntu-hello-[0-9]*.pkg.tar.zst ./ubuntu-hello-gtk-*.pkg.tar.zst
```

### Method 7: Snap (classic, amd64 only)
```bash
sudo snap install --dangerous --classic ubuntu-hello_*_amd64.snap
sudo snap run ubuntu-hello.host-install
```

### Method 8: AppImage (installer, amd64 + arm64)
```bash
chmod +x Ubuntu-Hello-*-$(uname -m).AppImage
./Ubuntu-Hello-*-$(uname -m).AppImage --install
```

### Method 9: Flatpak (installer, amd64 only)
```bash
flatpak install --user ./com.github.ventura8.UbuntuHello-*.flatpak && \
    flatpak run --command=ubuntu-hello-host-install com.github.ventura8.UbuntuHello
```
Approve the polkit prompt on the host-install step to install PAM and system files.

## 📋 Changelog (v1.2.7)

*   **Version:** `VERSION` is **1.2.7**.
*   **PAM (`ubuntu-hello/src/pam/main.cc`):** `ROOT_HELPER_TIMEOUT` (30 s). Root helpers are spawned in their own process group; `read_helper()` reads stdout with `poll()` against the deadline; `wait_for_helper()` polls `waitpid(WNOHANG)` and sends `SIGKILL` to the group at the deadline, returning -1. `run_root_helper()` takes an optional `timeout`.
*   **Tests:** `tests/pam_main_test.cc` covers hung, print-then-hang, held-stdout and slow helpers.
*   **Docs:** `docs/SECURITY.md` documents the helper time limit.
