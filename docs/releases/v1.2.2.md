# 🚀 Ubuntu Hello v1.2.2 Release

Welcome to the **v1.2.2** release of **Ubuntu Hello**! This release closes an integrity gap in how the setup wizard fetches the face-recognition models, which it downloads and unpacks as root, and fixes four ways enabling keyring unlock could go wrong: losing the previous seal when switching between TPM and software sealing, choosing TPM sealing on a partial `tpm2-tools` install, accepting an empty piped password, and a Settings edit deleting comments from `config.ini`. Under the hood, the project now runs **SonarQube Cloud** static analysis locally and in CI, and went from 356 findings to none.

---

## ✨ What's in v1.2.2

*   **🛡️ Security: the setup wizard verifies the face models it downloads.** When the models are missing, the wizard runs `dlib-data/install.sh` as root to fetch and unpack the three dlib archives. It unpacked whatever arrived: there was no integrity check, and the `github.com/.../raw/` URLs it used answer with a redirect. Each archive is now checked against a pinned SHA-256 before anything is unpacked. These are the same pins `package-configure.sh` already used for the packaged install path, so the two paths now agree, where before only one of them verified. Redirects are refused too: the canonical `raw.githubusercontent.com` URLs serve the files directly, so wget gets `--max-redirect=0` and curl gets `--max-redirs 0 --proto-redir =https`. A mismatch aborts the download, and the wizard reports a failed download.
*   **🔐 Fix: switching keyring unlock between TPM and software sealing could lose the seal.** Each sealing path deleted the other mechanism's credential before writing its own, so a failure in between left no usable seal. The previous credential is now kept until its replacement is on disk.
*   **🧰 Fix: `keyring enable` on a partial `tpm2-tools` install.** It chose TPM sealing when `tpm2_createprimary` and `tpm2_unseal` were present, then failed mid-seal without `tpm2_create` (used to seal) or `tpm2_load` (used to restore). All four are now required, with software sealing as the fallback.
*   **🚫 Fix: an empty piped password was sealed and reported as success.** Unsealing treats an empty result as failure, so that seal never unlocked anything. Empty piped input is now rejected, as the interactive prompt already did.
*   **📝 Fix: a Settings edit deleted comments from `config.ini`.** Indented `#`/`;` comments after a replaced key were treated as part of the old value. They are now kept, and the old value's real continuation lines are still dropped, so a `stamp_rules` update never leaves a stale rule behind.
*   **🔏 Fix: source installs set `config.ini` to `0744`.** Now `0644`, matching every package path and `docs/SECURITY.md`.
*   **⏱️ Fix: the auth window's last-resort user lookup** called `loginctl` with no timeout; it is now bounded at 5 seconds.
*   **🔎 New: SonarQube Cloud** — local (`./scripts/ci-sonar.sh`) and in CI, with a quality gate on `master` and same-repository pull requests (fork pull requests skip the scan; they cannot read the token). **356 findings → 0**; 0 bugs, 0 vulnerabilities, A ratings throughout.
*   **⚙️ CI: runs once per pull request** instead of twice, and the booted-OS tier runs on same-repository release pull requests.

## 📥 Installation

Download assets from the [GitHub Release](https://github.com/ventura8/ubuntu-hello/releases/tag/v1.2.2) page. Verify against `SHA256SUMS` before installing. Download this release's assets into an empty/clean directory before running these commands — the wildcards below match by filename pattern, and leftover assets from another version in the same directory can make a package manager see multiple matches (or, for the AppImage command, pass a second matched file as a stray argument).

### Method 1: Quick Install (from release tag)
Download and review [`install.sh`](https://github.com/ventura8/ubuntu-hello/blob/v1.2.2/install.sh) from the **v1.2.2** tag, then run `bash install.sh` locally.

### Method 2: PPA (Ubuntu / Linux Mint)
```bash
sudo add-apt-repository ppa:ventura8/ubuntu-hello
sudo apt update
sudo apt install ubuntu-hello
```

### Method 3: Debian `.deb` (amd64 + arm64)
```bash
sudo apt install ./ubuntu-hello_*_$(dpkg --print-architecture).deb ./ubuntu-hello-gtk_*_$(dpkg --print-architecture).deb
```

### Method 4: Fedora RPM (amd64 + arm64)
```bash
sudo dnf install ./ubuntu-hello-[0-9]*fc44*.$(uname -m).rpm ./ubuntu-hello-gtk-*fc44*.$(uname -m).rpm
```

### Method 5: openSUSE RPM (amd64 + arm64)
```bash
sudo zypper install ./ubuntu-hello-[0-9]*lp160*.$(uname -m).rpm ./ubuntu-hello-gtk-*lp160*.$(uname -m).rpm
```

### Method 6: Arch Linux (amd64 only)
```bash
sudo pacman -U ./ubuntu-hello-[0-9]*.pkg.tar.zst ./ubuntu-hello-gtk-*.pkg.tar.zst
```

### Method 7: Snap (classic, amd64 only)
```bash
sudo snap install --dangerous --classic ubuntu-hello_*_amd64.snap
sudo snap run ubuntu-hello.host-install
```

### Method 8: AppImage (installer, amd64 + arm64)
```bash
chmod +x Ubuntu-Hello-*-$(uname -m).AppImage
./Ubuntu-Hello-*-$(uname -m).AppImage --install
```

### Method 9: Flatpak (installer, amd64 only)
```bash
flatpak install --user ./com.github.ventura8.UbuntuHello-*.flatpak && \
    flatpak run --command=ubuntu-hello-host-install com.github.ventura8.UbuntuHello
```
Approve the polkit prompt on the host-install step to install PAM and system files.

## 📋 Changelog (v1.2.2)

*   **Release**: Version **`1.2.2`** / **`v1.2.2`** from repo-root **`VERSION`**; `debian/changelog` top entry added (`urgency=medium`).
*   **Security (model download)**: `ubuntu-hello/src/dlib-data/install.sh`, run as root by the setup wizard, verifies each archive against the SHA-256 pins shared with `scripts/package-configure.sh` before unpacking, and refuses redirects (canonical `raw.githubusercontent.com` URLs; wget `--max-redirect=0`, curl `--max-redirs 0 --proto-redir =https`). `set -eu`, a trap that removes partial temp files, and an explicit archive list instead of a glob. Exits non-zero on a mismatch, which `onboarding.py` reports as a failed download.
*   **Fix (keyring)**: `cli/keyring.py` — both seal paths write and `chmod` the new credential before removing the other mechanism's; `_tpm_usable()` requires `tpm2_createprimary`, `tpm2_create`, `tpm2_load` and `tpm2_unseal`; empty piped input to `keyring enable` is rejected. `run_keyring()` no longer reads `builtins.ubuntu_hello_args` unconditionally when called with explicit arguments (a latent crash, masked by test pollution). Keyring feature coverage stays at 100%.
*   **Fix (config editor)**: `config_edit.py` preserves indented comments inside a replaced multi-line value and still drops its continuation lines (`_consume_old_value()`).
*   **Fix (install)**: `install_config.py` installs `config.ini` as `0644` (was `0744`).
*   **Fix (GTK)**: the real-user lookup shared by `window.py`, `onboarding.py` and `authsticky.py` moved into `ubuntu-hello-gtk/src/real_user.py`, with each caller keeping its own source order; the `loginctl` call is bounded at 5 s everywhere (it had no timeout in `authsticky.py`). When the Settings window runs unelevated it keeps its `Gio.Settings` alive, so it keeps following the desktop theme. Settings search reads the displayed text of markup-only labels instead of the raw markup.
*   **Fix (rubber stamps)**: the rule regex no longer matches empty or backtracks between the trailing options and the preceding field.
*   **Static analysis**: `sonar-project.properties`, `scripts/ci-sonar.sh` (pinned `sonarsource/sonar-scanner-cli`, `--check-token` mode that validates the token and names an expired one), and a scan step in the CI `coverage` job, preceded by a workspace ownership reclaim (the root-run Docker stage leaves root-owned `__pycache__/`). Rule exclusions are scoped per rule and per path with the reason inline; `sonar.cfamily.reportingCppStandardOverride=c++17` matches `meson.build`. Refactors to bring cognitive complexity within limits across the PAM module (`identify_preflight()`, `gcm_open()`, `EnterDeviceError`), the keyring CLI, rubber stamps, onboarding, Settings and theme detection; 140 composite test assertions split; tests moved to `monkeypatch`.
*   **CI**: `check.yml` fires `push` for `master` only (a PR ran twice); the `vm` job runs on same-repository `feature/v*` pull requests and `workflow_dispatch`; `docker/setup-buildx-action` → `v4.4.1`, `docker/setup-qemu-action` → `v4.4.0`. The coverage stage writes `artifacts/coverage/coverage.xml`.
*   **Cleanup**: removed the dangling `ubuntu-hello/src/pam/.clang-tidy` symlink (clang-tidy already uses the root config); replaced the `pull_request_template.md` inherited from upstream.
*   **Docs**: `AGENTS.md`, `docs/INSTRUCTIONS.md` §5.1 (SonarQube Cloud), and the `ci-docker-matrix` and `test-runner` skills.
