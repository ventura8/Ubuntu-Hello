# Ubuntu Hello v1.1.5 - Setup Wizard Webcam-Testing Hang Fix

Bugfix release: the setup wizard's "Testing your webcams, please wait..." step could hang forever with no feedback and no way to proceed, depending on the camera driver.

---

## 🐛 Fixes

*   **Camera scan freeze**: `scan_cameras_thread()` had two unbounded blocking calls — a `udevadm` subprocess and `cv2.VideoCapture(...).read()` — with no timeout and no way to cancel. A single misbehaving driver could freeze the whole sequential scan forever. Both now have explicit 5s timeouts; the `VideoCapture` open+read runs on a watchdog thread, so a stuck device is reported unopenable and the scan moves on.
*   **Live preview opening the wrong device**: `open_camera_for_preview()` was opening the raw `/dev/v4l/by-path/...` symlink instead of resolving it to the real `/dev/videoN` device first — a regression from a later preview-thread rewrite that dropped the `os.path.realpath()` call still present in v1.1.2 and in this file's other two camera-opening call sites. This can make some V4L2/GStreamer driver+kernel combinations bind the wrong (or no) node, leaving the preview spinning with no frame and no error. Restored the resolution to match v1.1.2.
*   **Root cause: uncaught crash right after the scan finishes**: `on_camera_selection_changed()` referenced `self.slide2_preview_image`, an attribute that is never defined anywhere — a regression that doesn't exist in v1.1.2. This handler fires on every camera selection, including the automatic one right after "Testing your webcams" completes, so it threw on essentially every run and silently killed the preview at exactly that point. The unit test suite never caught it because it runs against a mocked `Gtk.Window` that auto-vivifies missing attributes instead of raising. Fixed to reset `preview_image` to the correct widget.
*   **Device list vanishing after a successful scan**: `update_camera_list_gui()` builds the camera list's `ScrolledWindow` at runtime with no minimum content height, so GTK could allocate it ~0 size (logged as `Negative content width/height` warnings) and the list silently disappeared even though the scan had succeeded and Next was already enabled — indistinguishable from a hang. v1.1.2 set `set_min_content_height(100)` here; a later rewrite dropped it. Restored, matching v1.1.2.
*   **Crash (SIGSEGV) on "Testing your webcams"**: confirmed from a real terminal run — the wizard segfaulted right after `gtk_widget_size_allocate(): attempt to allocate widget with width 0 and height -15` and `Negative content width/height ... GtkScrolledWindow`. Root cause: the device list's `CellRendererText` lost its `ellipsize` property in the same rewrite. Device names/paths can be arbitrarily long, and the list's `ScrolledWindow` disables horizontal scrolling; without ellipsizing, the unbounded column-width request against a fixed-width parent drove GTK to a negative allocation and crashed. Restored `ellipsize`, matching v1.1.2.
*   **The real root cause — device list stayed invisible even with the crash fixed** (`onboarding.glade`): `slidecontainer` had the deprecated GtkBox `resize-mode="immediate"` property set. Isolated in a minimal standalone test: with this property set, any widget added at runtime to an already-visible descendant box — exactly what happens when the device list is built after the scan finishes — permanently collapses to a 1×1 allocation, no matter how many further resize requests follow. Removed the property.
*   **Live preview always black, even for a working camera**: the scan itself successfully captured and analyzed a frame (showing "Yes, compatible infrared camera"), but the live preview box stayed solid black. Root cause: `update_preview_image_widget()` decodes frames via `GdkPixbuf` (aliased `pixbuf`), but that alias was only ever imported locally inside a sibling method, never at module scope — every call raised `NameError`, silently swallowed by a bare `except`. Fixed by importing `GdkPixbuf` at module level.
*   **Verified against real hardware and real terminal runs, not just synthetic reproduction**: an actual `ubuntu-hello-gtk --force-onboarding` run reproduced the segfault above before the crash fix; after it, the same run completes with no GTK warnings and no crash. After the `resize-mode` fix, the device list renders correctly on real hardware, showing per-camera results. Debug logging then pinpointed the preview `NameError`; after the fix, live frames display correctly. Added regression tests covering these issues.

## 📥 Installation (from Release assets)

Verify downloads against `SHA256SUMS` on the Release page before installing. Download this release's assets into an empty/clean directory before running these commands — the wildcards below match by filename pattern, and leftover assets from another version in the same directory can make a package manager see multiple matches (or, for the AppImage command, pass a second matched file as a stray argument).

| Format | Command |
|--------|---------|
| **Debian** (amd64 + arm64) | `sudo apt install ./ubuntu-hello_*_$(dpkg --print-architecture).deb ./ubuntu-hello-gtk_*_$(dpkg --print-architecture).deb` |
| **Fedora** (amd64 + arm64) | `sudo dnf install ./ubuntu-hello-[0-9]*fc44*.$(uname -m).rpm ./ubuntu-hello-gtk-*fc44*.$(uname -m).rpm` |
| **openSUSE** (amd64 + arm64) | `sudo zypper install ./ubuntu-hello-[0-9]*lp160*.$(uname -m).rpm ./ubuntu-hello-gtk-*lp160*.$(uname -m).rpm` |
| **AppImage** (amd64 + arm64) | `chmod +x Ubuntu-Hello-*-$(uname -m).AppImage && ./Ubuntu-Hello-*-$(uname -m).AppImage --install` |
| **Arch** (amd64 only) | `sudo pacman -U ./ubuntu-hello-[0-9]*.pkg.tar.zst ./ubuntu-hello-gtk-*.pkg.tar.zst` |
| **Snap** (amd64 only) | `sudo snap install --dangerous --classic ubuntu-hello_*_amd64.snap && sudo snap run ubuntu-hello.host-install` |
| **Flatpak** (amd64 only) | `flatpak install --user ./com.github.ventura8.UbuntuHello-*.flatpak && flatpak run --command=ubuntu-hello-host-install com.github.ventura8.UbuntuHello && flatpak run com.github.ventura8.UbuntuHello` |

PPA remains available:

```bash
sudo add-apt-repository ppa:ventura8/ubuntu-hello && sudo apt update && sudo apt install ubuntu-hello
```

Optional source install: download `install.sh` from the [v1.1.5 tag](https://github.com/ventura8/ubuntu-hello/tree/v1.1.5), review it, then run locally — do not pipe a moving branch URL directly to `bash`.
