# 🚀 Ubuntu Hello v1.2.8 Release

Welcome to the **v1.2.8** release of **Ubuntu Hello**! This release adds a one-click repair for a login keyring that stopped accepting your password, and detects the problem in Settings.

---

## ✨ What's in v1.2.8

*   **🔑 Repair a login keyring that stopped unlocking.** A login keyring can get damaged, or its password can drift away from your login password (seen after another app wrote to the keyring while it was open). Face login still works, but the keyring then rejects every password: the one Ubuntu Hello hands over and the one you type. Until now that failed silently and left you with keyring prompts. New **`sudo ubuntu-hello keyring repair`** stores your current password first, then renames the old `login.keyring` to `login.keyring.broken-<date>` (kept, never deleted). Your next login creates a fresh keyring that unlocks automatically. Passwords saved in the old keyring need to be entered again. GNOME Keyring only; KWallet users are pointed to System Settings.
*   **⚠️ Settings detects it for you.** When auto-unlock is on and your login keyring is still locked in your running session, the **Keyring** tab shows a warning and a **Repair Keyring** button that runs the same repair after checking your password.
*   **📖 Troubleshooting.** The README explains how to tell a broken keyring from a face-login problem: if your typed password is rejected too, the keyring is the cause.
*   **🧹 Code quality.** Clears the SonarCloud findings in the PAM helper wait loop. The signal-retry logic is now one small function, and a new test interrupts a real wait with a signal to prove it retries.

Nine new translatable strings, translated in all 98 languages. No new config keys.

## 📥 Installation

Download assets from the [GitHub Release](https://github.com/ventura8/ubuntu-hello/releases/tag/v1.2.8) page. Verify against `SHA256SUMS` before installing. Download this release's assets into an empty/clean directory before running these commands — the wildcards below match by filename pattern, and leftover assets from another version in the same directory can make a package manager see multiple matches (or, for the AppImage command, pass a second matched file as a stray argument).

### Method 1: Quick Install (from release tag)
Download and review [`install.sh`](https://github.com/ventura8/ubuntu-hello/blob/v1.2.8/install.sh) from the **v1.2.8** tag, then run `bash install.sh` locally.

### Method 2: PPA (Ubuntu / Linux Mint)
```bash
sudo add-apt-repository ppa:ventura8/ubuntu-hello
sudo apt update
sudo apt install ubuntu-hello
```
Builds for Ubuntu **22.04 (jammy)**, 24.04 (noble) and 26.04 (resolute), and derivatives on them (Linux Mint 21 / 22). **On 22.04, use the PPA**: the `.deb` Release assets below are built on 26.04 and do not install there.

### Method 3: Debian `.deb` (amd64 + arm64)
```bash
sudo apt install ./ubuntu-hello_*_$(dpkg --print-architecture).deb ./ubuntu-hello-gtk_*_$(dpkg --print-architecture).deb
```

### Method 4: Fedora RPM (amd64 + arm64)
```bash
sudo dnf install ./ubuntu-hello-[0-9]*fc44*.$(uname -m).rpm ./ubuntu-hello-gtk-*fc44*.$(uname -m).rpm
```

### Method 5: openSUSE RPM (amd64 + arm64)
```bash
sudo zypper install ./ubuntu-hello-[0-9]*lp160*.$(uname -m).rpm ./ubuntu-hello-gtk-*lp160*.$(uname -m).rpm
```

### Method 6: Arch Linux (amd64 only)
```bash
sudo pacman -U ./ubuntu-hello-[0-9]*.pkg.tar.zst ./ubuntu-hello-gtk-*.pkg.tar.zst
```

### Method 7: Snap (classic, amd64 only)
```bash
sudo snap install --dangerous --classic ubuntu-hello_*_amd64.snap
sudo snap run ubuntu-hello.host-install
```

### Method 8: AppImage (installer, amd64 + arm64)
```bash
chmod +x Ubuntu-Hello-*-$(uname -m).AppImage
./Ubuntu-Hello-*-$(uname -m).AppImage --install
```

### Method 9: Flatpak (installer, amd64 only)
```bash
flatpak install --user ./com.github.ventura8.UbuntuHello-*.flatpak && \
    flatpak run --command=ubuntu-hello-host-install com.github.ventura8.UbuntuHello
```
Approve the polkit prompt on the host-install step to install PAM and system files.

## 📋 Changelog (v1.2.8)

*   **Version:** `VERSION` is **1.2.8**.
*   **CLI (`ubuntu-hello/src/cli/keyring.py`):** new `keyring repair` action. Seals the password (TPM or software, same as `enable`), then renames `~/.local/share/keyrings/login.keyring` to `login.keyring.broken-<timestamp>`. A failed seal leaves the keyring untouched; refuses on KWallet.
*   **Core (`keyring_restore.py`):** `login_keyring_locked()` reads the login collection's `Locked` property over the user's session bus (`None` when unknown or KWallet).
*   **GTK (`tab_keyring.py`, `main.ui`, `window.py`):** broken-keyring warning and **Repair Keyring** button; enable and repair share one password prompt and CLI call.
*   **PAM (`ubuntu-hello/src/pam/main.cc`):** `waitpid_no_eintr()` replaces the two EINTR loops in `wait_for_helper()` (SonarCloud S6004, S108).
*   **Tests:** probe, CLI repair (seal-before-move order, failed seal, missing keyring, rename failure, KWallet), GTK repair flow, and a real `SIGALRM` interrupting `waitpid` in `pam_main_test`.
*   **i18n:** 9 new strings in all 98 catalogs; catalog source references refreshed.
*   **Docs:** README troubleshooting, `docs/INSTRUCTIONS.md`, `docs/architecture/README.md`, keyring-wallet skill, `AGENTS.md`.
