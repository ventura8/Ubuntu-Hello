# Ubuntu Hello v1.1.4 - ARM64 Release Artifacts (deb, Fedora/openSUSE RPM, AppImage)

`.deb`, Fedora RPM, openSUSE RPM, and AppImage Release assets now ship for both **amd64** and **arm64** — built via QEMU cross-build in `release.yml` and verified with the same live install → upgrade → remove → reinstall E2E cycle used for amd64. Arch, Snap, and Flatpak stay amd64-only, each for a concrete reason documented below.

---

## 🦾 ARM64 Coverage

*   **Workflow**: [`.github/workflows/release.yml`](https://github.com/ventura8/ubuntu-hello/blob/v1.1.4/.github/workflows/release.yml) — `build-deb`, `build-rpm-fedora`, `build-rpm-opensuse`, and `build-appimage` run a matrix over `amd64`/`arm64`; arm64 legs use `docker/setup-qemu-action` + `docker build/run --platform linux/arm64`.
*   **Verified, not just built**: each arch runs `packaging-smoke-verify.sh` then `packaging-e2e-install.sh` (install → upgrade → remove → reinstall) against its own image before upload.
*   **AppImage fix**: type-2 AppImages encode an `"AI\x02"` signature into ELF `e_ident` bytes that the standard `qemu-user-static` binfmt_misc registration rejects, so executing an AppImage directly under cross-arch emulation fails with "Exec format error". `uh_appimage_squashfs_offset()` in [`scripts/release-common.sh`](https://github.com/ventura8/ubuntu-hello/blob/v1.1.4/scripts/release-common.sh) parses the ELF header to find the squashfs offset and extracts with `unsquashfs` instead — used for both the downloaded `appimagetool` and our own built output AppImage, with a fallback to direct execution if `unsquashfs` or offset detection is unavailable.

## 🚫 Staying amd64-only

*   **Arch**: the official `archlinux` Docker image has no arm64 manifest.
*   **Snap**: deferred — systemd+snapd under QEMU emulation is unreliable.
*   **Flatpak**: `flatpak-builder`'s `bwrap` sandbox requires Linux user namespaces, which QEMU user-mode emulation doesn't support.

## 📥 Installation (from Release assets)

Verify downloads against `SHA256SUMS` on the Release page before installing.

| Format | Command |
|--------|---------|
| **Debian** (amd64 + arm64) | `sudo apt install ./ubuntu-hello_*_$(dpkg --print-architecture).deb ./ubuntu-hello-gtk_*_$(dpkg --print-architecture).deb` |
| **Fedora** (amd64 + arm64) | `sudo dnf install ./ubuntu-hello-[0-9]*fc44*.$(uname -m).rpm ./ubuntu-hello-gtk-*fc44*.$(uname -m).rpm` |
| **openSUSE** (amd64 + arm64) | `sudo zypper install ./ubuntu-hello-[0-9]*lp160*.$(uname -m).rpm ./ubuntu-hello-gtk-*lp160*.$(uname -m).rpm` |
| **AppImage** (amd64 + arm64) | `chmod +x Ubuntu-Hello-*-$(uname -m).AppImage && ./Ubuntu-Hello-*-$(uname -m).AppImage --install` |
| **Arch** (amd64 only) | `sudo pacman -U ./ubuntu-hello-[0-9]*.pkg.tar.zst ./ubuntu-hello-gtk-*.pkg.tar.zst` |
| **Snap** (amd64 only) | `sudo snap install --dangerous --classic ubuntu-hello_*_amd64.snap && sudo snap run ubuntu-hello.host-install` |
| **Flatpak** (amd64 only) | `flatpak install --user ./com.github.ventura8.UbuntuHello-*.flatpak && flatpak run --command=ubuntu-hello-host-install com.github.ventura8.UbuntuHello && flatpak run com.github.ventura8.UbuntuHello` |

PPA remains available:

```bash
sudo add-apt-repository ppa:ventura8/ubuntu-hello && sudo apt update && sudo apt install ubuntu-hello
```

Optional source install: download `install.sh` from the [v1.1.4 tag](https://github.com/ventura8/ubuntu-hello/tree/v1.1.4), review it, then run locally — do not pipe a moving branch URL directly to `bash`.
