# Ubuntu Hello v1.1.7 - Keyring-Unseal Fix, Second-Model Wizard, Auth Notifications + Hardening

This release fixes TPM-sealed keyring unlock under polkit, teaches the setup wizard to enroll a second face model for different lighting, adds native desktop notifications for every face-auth attempt (with the diagnostics behind the result), hardens how the root PAM module launches its `compare.py` helper, and refreshes every product and CI dependency pin to its latest final release. The hardening was in response to an automated vulnerability-scanner report of a potential **local privilege escalation via a user-controlled `PATH`**. On review the chain was **not exploitable as described** (details below), but the code relied on an unspecified corner of libc behaviour, so it is now explicit and no longer depends on it.

---

## 🔒 What's in this release

*   **Reported**: `pam_ubuntu_hello.so` spawned `compare.py` as root with `posix_spawnp(..., envp = nullptr)` and never dropped privileges; `compare.py` then started the auth overlay with `subprocess.Popen(["ubuntu-hello-gtk", ...])` — a bare-name `PATH` lookup. The scanner concluded that a local user could plant `~/.local/bin/ubuntu-hello-gtk` and have it executed as root the moment face auth started (e.g. `su <enrolled-user>`).
*   **Why it was not exploitable**: on glibc/Linux, `posix_spawnp()` with a `NULL` `envp` gives the child an **empty** environment, not the caller's — verified with a small test program (`FOO=bar ./t` → `env` prints nothing). With no `PATH` set at all, both glibc's `execvp()` and Python's `subprocess` fall back to `/bin:/usr/bin`, so `ubuntu-hello-gtk` already resolved to `/usr/bin/ubuntu-hello-gtk`; `~/.local/bin` was never searched. The premise of an "inherited environment" was wrong.
*   **Hardened anyway — PAM module**: the helper is now started with `posix_spawn()` and an **explicit minimal environment** (`PATH=/usr/sbin:/usr/bin:/sbin:/bin` only), so the calling user's `PATH`, `PYTHONPATH`, `LD_PRELOAD`, … can never reach the root helper regardless of libc behaviour. The interpreter runs as `python3 -E -s` (ignore `PYTHON*` variables, no user site-packages). `-I` was deliberately **not** used: it would also drop the script directory from `sys.path`, which would break `compare.py`'s sibling imports (`snapshot`, `paths_factory`, `recorders`, …).
*   **Hardened anyway — `compare.py`**: the auth overlay is now spawned via an absolute path (`GTK_BIN_PATH = "/usr/bin/ubuntu-hello-gtk"`), matching the existing `BUSCTL_PATH` pattern. No child of the root helper is resolved by bare name any more.
*   **Hardened — AuthNotifier markers**: privileged `notify.py` writes id / `.done` files under `/run/ubuntu-hello/notify/<uid>/` with `O_NOFOLLOW` (and `O_EXCL` for the pid tmp) instead of following a user-planted symlink under `/run/user/<uid>/` as root.
*   **Docs**: `docs/SECURITY.md` gains a **"No Inherited Environment / PATH"** bullet; `docs/architecture/README.md` §3.1 and `AGENTS.md` now describe the explicit-env spawn and `-E -s` flags.
*   **🔑 Fix: TPM-sealed keyring unlock failed under polkit (worked at GDM)**: every `pkexec` / App Center prompt logged `Failed to unseal keyring password from TPM`. polkit ≥ 126 runs `polkit-agent-helper-1` as a hardened transient unit (`DevicePolicy=strict`, `ProtectSystem=strict`); the shipped drop-in only re-allowed the camera and `/dev/uinput`, so `/dev/tpmrm0` was `Operation not permitted` and the transient `.ctx` files under `/etc/ubuntu-hello/tpm-keys/` hit a read-only filesystem. All three drop-in writers (`install.sh`, `package-configure.sh`, `install_config.py`) now add `DeviceAllow=char-tpm rw`, `DeviceAllow=/dev/tpm0 rw`, `ReadWritePaths=/etc/ubuntu-hello/tpm-keys`. Reproduced layer-by-layer with `systemd-run` under the unit's exact hardening and verified live: `PAM_AUTHTOK set successfully for keyring unlocking` on a real polkit prompt. Regression tests in `test_install_download.py` / `test_packaging_release.py`.
*   **🧑‍🎨 Setup wizard: second face model under different lighting**: a single model recorded in daylight often lands just past the certainty threshold in the evening under lamps (or vice-versa), which shows up as intermittent "timeout reached" instead of a clear error (root-caused on real hardware: certainty 3.37–3.6 vs 3.5). Slide 4 now runs two passes: after the first scan it re-labels itself **"Add a second face model (recommended)"**, explains *why* (lighting) and *how* (change the room light / desk lamp, turn away from the window, put on the glasses you sometimes wear), restarts the live preview and offers **Scan second model**. Either pass can be skipped, **but not both**: skipping pass 1 makes pass 2 required (Skip hidden, "Add a face model (required)"); a failed second scan is non-fatal (retry or skip) whereas a failed only-scan still stops the wizard. Models are labelled `Setup lighting 1` / `Setup lighting 2`. **Settings** also shows a warning bar on the Models tab while exactly one model is enrolled, with an **Add a second model** action. 18 new strings translated in all 98 catalogs. Unit tests + real-GTK E2E (`UH_REAL_GTK=1`) cover both passes and both skip paths.
*   **🔔 New: native desktop notifications for every face-auth attempt** (`notify.py`, `org.freedesktop.Notifications`): one card **updated in place** — "Face authentication · sudo — 👀 Looking for your face…" stays on screen for the **whole scan** (critical urgency: GNOME never auto-hides it), then becomes **Face recognized · sudo — ✓ Full Name · 1.3 s** (removed after `success_linger` = 3 s) or **Face not recognized — ✗ No match in 8 s · 💡 add a model in this light** (stays in the list). Titles name the requester (`sudo`, `su`, `authorization`, `screen unlock`) because the PAM module now forwards the PAM service to `compare.py`. `[notifications] details = true` adds model, certainty/threshold, frames, dark frames, camera, pid, timeout, load. Privileged PAM compare persists the notification id under `/run/ubuntu-hello/notify/<uid>/` (`0700`, `O_NOFOLLOW`); unprivileged dry runs still use the XDG runtime-dir files. A detached helper closes the success card and acts as a watchdog for a helper that died mid-scan. Layout follows GNOME Shell 50's rules read from its source (one-line body, `<b>` only; no `desktop-entry`/`transient`; low urgency never banners). Because `compare.py` runs as root with an empty environment, cards are sent on the **target user's** session bus by dropping to that uid before exec'ing the absolute `/usr/bin/gdbus`; greeter logins, missing gdbus, or any error silently disable it — never the auth result. Verified live on GNOME 50 / Wayland. Strings translated in all 98 catalogs; `libglib2.0-bin` / `glib2` added to core runtime deps.

## 📥 Installation (from Release assets)

Verify downloads against `SHA256SUMS` on the Release page before installing. Download this release's assets into an empty/clean directory before running these commands — the wildcards below match by filename pattern, and leftover assets from another version in the same directory can make a package manager see multiple matches (or, for the AppImage command, pass a second matched file as a stray argument).

| Format | Command |
|--------|---------|
| **Debian** (amd64 + arm64) | `sudo apt install ./ubuntu-hello_*_$(dpkg --print-architecture).deb ./ubuntu-hello-gtk_*_$(dpkg --print-architecture).deb` |
| **Fedora** (amd64 + arm64) | `sudo dnf install ./ubuntu-hello-[0-9]*fc44*.$(uname -m).rpm ./ubuntu-hello-gtk-*fc44*.$(uname -m).rpm` |
| **openSUSE** (amd64 + arm64) | `sudo zypper install ./ubuntu-hello-[0-9]*lp160*.$(uname -m).rpm ./ubuntu-hello-gtk-*lp160*.$(uname -m).rpm` |
| **AppImage** (amd64 + arm64) | `chmod +x Ubuntu-Hello-*-$(uname -m).AppImage && ./Ubuntu-Hello-*-$(uname -m).AppImage --install` |
| **Arch** (amd64 only) | `sudo pacman -U ./ubuntu-hello-[0-9]*.pkg.tar.zst ./ubuntu-hello-gtk-*.pkg.tar.zst` |
| **Snap** (amd64 only) | `sudo snap install --dangerous --classic ubuntu-hello_*_amd64.snap && sudo snap run ubuntu-hello.host-install` |
| **Flatpak** (amd64 only) | `flatpak install --user ./com.github.ventura8.UbuntuHello-*.flatpak && flatpak run --command=ubuntu-hello-host-install com.github.ventura8.UbuntuHello` |

PPA remains available:

```bash
sudo add-apt-repository ppa:ventura8/ubuntu-hello && sudo apt update && sudo apt install ubuntu-hello
```

Optional source install: download [`install.sh`](https://github.com/ventura8/ubuntu-hello/blob/v1.1.7/install.sh) from the **v1.1.7** tag, review it, then run locally — do not pipe a moving branch URL directly to `bash`.
