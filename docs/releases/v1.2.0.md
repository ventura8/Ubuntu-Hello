# 🚀 Ubuntu Hello v1.2.0 Release

Welcome to the **v1.2.0** release of **Ubuntu Hello**! This release fixes TPM-sealed keyring unlock under polkit, adds a second-model pass to the setup wizard, introduces native desktop notifications for face authentication, moves the whole GTK side (Settings, wizard, overlay) to **GTK 4**, hardens the root PAM compare helper, and refreshes every product and CI dependency pin to its latest final release. Hardening scope: how `pam_ubuntu_hello.so` launches `compare.py`, and how `compare.py` launches its own children. It was prompted by an automated vulnerability-scanner report of a potential **local privilege escalation via a user-controlled `PATH`**. On review the chain was **not exploitable as described** — but the code relied on an unspecified corner of libc behaviour, so it is now explicit and no longer depends on it.

---

## ✨ What's in v1.2.0

*   **🔒 The report**: `pam_ubuntu_hello.so` spawned `compare.py` as root with `posix_spawnp(..., envp = nullptr)` and never dropped privileges. `compare.py` then started the auth overlay with `subprocess.Popen(["ubuntu-hello-gtk", "--start-auth-ui"])` — a bare-name `PATH` lookup — while the same file already hardcoded `/usr/bin/busctl` for exactly this reason. The scanner concluded that any local user could plant `~/.local/bin/ubuntu-hello-gtk` (Ubuntu's default interactive `PATH` puts `~/.local/bin` first) and have it executed as root the moment face auth started — before any match, even if auth later failed — via `su <enrolled-user>`, since the module is installed as a PAM Primary in `common-auth`.
*   **🔍 Why it was not exploitable**: the premise of an "inherited environment" was wrong. On glibc/Linux, `posix_spawnp()` with a `NULL` `envp` gives the child an **empty** environment, not the caller's — verified with a small C test program (`FOO=bar ./t` → child's `env` prints nothing). With no `PATH` variable at all, both glibc's `execvp()` and Python's `subprocess` (`os.get_exec_path()` → `os.defpath`) fall back to `/bin:/usr/bin`, so `ubuntu-hello-gtk` already resolved to `/usr/bin/ubuntu-hello-gtk` and `~/.local/bin` was never consulted. However, POSIX does not define `NULL` `envp` for `posix_spawn`; the safe outcome was a libc implementation detail, not a guarantee.
*   **🛡️ Hardened — PAM module (`ubuntu-hello/src/pam/main.cc`)**:
    *   `compare.py` is now started with `posix_spawn()` (not `posix_spawnp()`) and an **explicit minimal environment**: `envp = {"PATH=/usr/sbin:/usr/bin:/sbin:/bin"}`. The calling user's `PATH`, `PYTHONPATH`, `LD_PRELOAD`, `LD_LIBRARY_PATH`, … can never reach the root helper regardless of libc behaviour.
    *   The interpreter is invoked as `python3 -E -s <compare.py> <user>`: `-E` ignores all `PYTHON*` environment variables, `-s` disables the user site-packages directory. Nothing outside the packaged install can inject code into the helper.
    *   `-I` (isolated mode) was deliberately **not** used, even though the scanner suggested it: `-I` also removes the script's own directory from `sys.path`, which would break `compare.py`'s sibling imports (`snapshot`, `paths_factory`, `recorders.video_capture`, `i18n`). Confirmed `-E -s` keeps the script directory on `sys.path`.
*   **🛡️ Hardened — `compare.py`**: the auth overlay is now spawned via an absolute path — new module constant `GTK_BIN_PATH = "/usr/bin/ubuntu-hello-gtk"`, next to the existing `BUSCTL_PATH`, with the shared comment updated to cover both. No child of the root helper is resolved by bare name any more. The existing `FileNotFoundError` fallback (overlay optional) is unchanged.
*   **📚 Docs**: `docs/SECURITY.md` gains a **"No Inherited Environment / PATH"** bullet alongside "No Shell Interpolation"; `docs/architecture/README.md` §3.1 now shows the explicit-env `posix_spawn` and notes that `compare.py` spawns `busctl` / `ubuntu-hello-gtk` by absolute path only; `AGENTS.md`'s sequence diagram and process-spawning rule updated to match.
*   **🔑 Fix: TPM-sealed keyring unlock failed under polkit (worked at GDM)**: every `pkexec` / App Center prompt logged `Failed to unseal keyring password from TPM`. polkit ≥ 126 runs `polkit-agent-helper-1` as a hardened transient unit (`DevicePolicy=strict`, `ProtectSystem=strict`); the shipped drop-in only re-allowed the camera and `/dev/uinput`, so `/dev/tpmrm0` was `Operation not permitted` and the transient `.ctx` files under `/etc/ubuntu-hello/tpm-keys/` hit a read-only filesystem. All three drop-in writers (`install.sh`, `package-configure.sh`, `install_config.py`) now add `DeviceAllow=char-tpm rw`, `DeviceAllow=/dev/tpm0 rw`, `ReadWritePaths=/etc/ubuntu-hello/tpm-keys`. Reproduced layer-by-layer with `systemd-run` under the unit's exact hardening and verified live: `PAM_AUTHTOK set successfully for keyring unlocking` on a real polkit prompt. Regression tests in `test_install_download.py` / `test_packaging_release.py`.
*   **🧑‍🎨 Setup wizard: second face model under different lighting**: a single model recorded in daylight often lands just past the certainty threshold in the evening under lamps (or vice-versa), which shows up as intermittent "timeout reached" instead of a clear error (root-caused on real hardware: certainty 3.37–3.6 vs 3.5). Slide 4 now runs two passes: after the first scan it re-labels itself **"Add a second face model (recommended)"**, explains *why* (lighting) and *how* (change the room light / desk lamp, turn away from the window, put on the glasses you sometimes wear), restarts the live preview and offers **Scan second model**. Either pass can be skipped, **but not both**: skipping pass 1 makes pass 2 required (Skip hidden, "Add a face model (required)"); a failed second scan is non-fatal (retry or skip) whereas a failed only-scan still stops the wizard. Models are labelled `Setup lighting 1` / `Setup lighting 2`. **Settings** also shows a warning bar on the Models tab while exactly one model is enrolled, with an **Add a second model** action. 18 new strings translated in all 98 catalogs. Unit tests + real-GTK E2E (`UH_REAL_GTK=1`) cover both passes and both skip paths.
*   **🔔 New: native desktop notifications for every face-auth attempt** (`notify.py`, `org.freedesktop.Notifications`): one card **updated in place** — "Face authentication · sudo — 👀 Looking for your face…" stays on screen for the **whole scan** (critical urgency: GNOME never auto-hides it), then becomes **Face recognized · sudo — ✓ Full Name · 1.3 s** (removed after `success_linger` = 3 s) or **Face not recognized — ✗ No match in 8 s · 💡 add a model in this light** (stays in the list). Titles name the requester (`sudo`, `su`, `authorization`, `screen unlock`) because the PAM module now forwards the PAM service to `compare.py`. `[notifications] details = true` adds model, certainty/threshold, frames, dark frames, camera, pid, timeout, load. The notification id is persisted per user so consecutive attempts reuse the **same card**; a detached helper closes the success card and acts as a watchdog for a helper that died mid-scan. Layout follows GNOME Shell 50's rules read from its source (one-line body, `<b>` only; no `desktop-entry`/`transient`; low urgency never banners). Because `compare.py` runs as root with an empty environment, cards are sent on the **target user's** session bus by dropping to that uid before exec'ing the absolute `/usr/bin/gdbus`; greeter logins, missing gdbus, or any error silently disable it — never the auth result. Verified live on GNOME 50 / Wayland, including a real polkit prompt: the polkit helper drop-in now sets `ProtectHome=tmpfs` + `BindPaths=/run/user` (`yes` hid `/run/user`, so no card could ever be delivered from Settings / App Center / `pkexec`; `/home` and `/root` stay empty inside the unit, only the runtime dir is bound back — security review) and `ReadWritePaths=-/run/ubuntu-hello` for the root-only id state, created at boot by a new `tmpfiles.d/ubuntu-hello.conf`. Strings translated in all 98 catalogs; `libglib2.0-bin` / `glib2` added to core runtime deps.
*   **⚙️ Settings → Notifications tab**: switches for *Show notifications*, *Notification sounds* and *Include diagnostics* (`[notifications] enabled/sound/details`), written with a new comment-preserving `config_edit.set_option()` (the bare-key `ubuntu-hello set` is ambiguous between sections). "Add new user" removed from the Models tab. Wizard: **Back** button on every page after the first (Cancel only on page 1) with per-page cleanup — camera scan cancelled and single device list on re-entry, chosen camera kept selected, IR test capture released, download not restarted, second scan resumed instead of a third model. First scan is required, only the second can be skipped; the two-scan plan is explained up front.
*   **🧱 GTK 4 migration (Settings app, setup wizard, auth overlay)**: `ubuntu-hello-gtk` moves from GTK 3 + Glade to **GTK 4 + GtkBuilder `.ui`** (`main.ui`, `onboarding.ui`, converted with `gtk4-builder-tool simplify --3to4` and validated with `gtk4-builder-tool validate`). Trigger: on GTK 3 the Language combo's popup grew to the height of the screen with 98 entries; GTK 4's `ComboBoxText` scrolls. The port keeps stock widgets (`HeaderBar` / `Notebook` / `SearchEntry` / `ComboBoxText` / `MessageDialog` / `TreeView`) and adds a tiny `gtk4compat.py` for the APIs GTK 4 removed: `run_main`/`quit_main` (no `Gtk.main`), `run_dialog` (no `Dialog.run`; nested `GLib.MainLoop` keeps the wizard's synchronous question/answer flow), `iter_children`, `builder(scope, …)` (no `connect_signals`), `pixbuf_to_texture` (`Gtk.Picture` paintables). Camera previews and logos are `GtkPicture` (GTK 4's `GtkImage` scales pictures down to icon size); the wizard's camera page keeps a fixed 300 px preview so the device list keeps its room and scrolls the preselected camera fully into view. Settings and wizard follow the desktop theme even when elevated: the user's GTK theme name (Yaru accent variant, `-dark` suffix matched to the light/dark preference) is applied via `gtk-theme-name` next to the existing prefer-dark handling. Wrapping labels cap at 70 chars so windows no longer grow to the text's full width. **GTK 4 design language**: no widgets deprecated in GTK 4.10 remain — `ComboBoxText` → `DropDown` (with type-ahead search; the 98-language list scrolls), `TreeView`/`ListStore` → `ColumnView` + `Gio.ListStore`, `MessageDialog`/`Dialog` → `AlertDialog` and small modal `PromptWindow`s, `InfoBar` → a `Revealer` banner; `tests/test_no_deprecated_gtk.py` guards against regressions. Every wizard page and Settings tab uses one idiom: symbolic glyph, large title, dimmed hint and card groups (`.uh-card`); the infrared-emitter page has icon buttons ("Yes, it flashes" / "No, nothing flashes"). No hard-coded fonts/colours (theme link colour, system font). Settings pins a 900×620 default size, the Video preview is a fixed 400×300 picture, and switching tabs no longer pops a dropdown list open (GTK moves focus into the page; focus is settled after the switch). **Language switch**: the new content is transplanted into the *same* toplevel (destroying and recreating the Settings window while popups/stacking state referenced it made GNOME Shell/mutter 50 hit `meta_window_set_stack_position` assertions and finally segfault, logging the user out); the rebuild is deferred to the main loop after the dropdown list is closed (rebuilding from inside its handler froze GTK 4); `.ui` strings are translated with the app's Python gettext before loading (C gettext ignores `LANGUAGE` under a C/C.UTF-8 locale — root under pkexec, CI), and `_`/`ngettext` are dynamic so every module follows the switch (fixes the untranslated *Unknown* on the Video tab). **Right-to-left**: Arabic, Hebrew, Persian, Urdu, Pashto, Sindhi and Yiddish mirror the whole UI (`Gtk.Widget.set_default_direction`, sidebar tabs on the right, start/end navigation swapped); new E2E `tests/e2e/test_language_rtl_e2e.py` switches to German and navigates everything with real catalogs, then audits the Arabic layout (mirrored header search, sidebar, banner, wizard navigation, every visible label translated and RTL). About gains a *Report a problem or suggest a feature* link to GitHub issues; About links open in the **user's** browser with the session environment forwarded (as root under pkexec, `xdg-open` previously lost the URL). Root cause of the language-switch freeze on Wayland: the search "reveal page" walker force-showed every descendant of a tab, including the dropdowns' list popovers — mapping a grabbing popup while the window is not topmost leaves the app unresponsive (and was why dropdowns opened by themselves on tab switch); popovers are now never touched, verified on a headless mutter Wayland session. Dropdown type-ahead search matches substrings case- and accent-insensitively (GTK's default is prefix-only) with an E2E typing into the real popover; the header settings search is also accent-insensitive, Escape clears it and Ctrl+F focuses it. Cameras are named by brand and model from udev (`Azurewave USB2.0 HD UVC WebCam (video-index0)`) in the wizard list and the Settings camera dropdown (`camera_names.py`), dropdown popups grow to their widest full name, and the About icon is recentred (face + check badge smaller). Every issue found in manual testing has a unit guard (`tests/test_ui_layout_guards.py`, `tests/test_window_unit.py`, `tests/test_i18n_dynamic.py`) and an end-to-end regression (`tests/e2e/test_manual_regressions_e2e.py`). Radio choices are `GtkCheckButton` + `group`; the overlay draws via `DrawingArea.set_draw_func` + `GestureClick` and polls stdin with `GLib.io_add_watch`; CSS goes through `add_provider_for_display`. ## 📥 Installation

Download assets from the [GitHub Release](https://github.com/ventura8/ubuntu-hello/releases/tag/v1.2.0) page. Verify against `SHA256SUMS` before installing.

### Method 1: Quick Install (from release tag)
Download and review [`install.sh`](https://github.com/ventura8/ubuntu-hello/blob/v1.2.0/install.sh) from the **v1.2.0** tag, then run `bash install.sh` locally.

### Method 2: PPA (Ubuntu / Linux Mint)
```bash
sudo add-apt-repository ppa:ventura8/ubuntu-hello
sudo apt update
sudo apt install ubuntu-hello
```

### Method 3: Debian `.deb` (amd64 + arm64)
```bash
sudo apt install ./ubuntu-hello_1.2.0-1ppa1_$(dpkg --print-architecture).deb ./ubuntu-hello-gtk_1.2.0-1ppa1_$(dpkg --print-architecture).deb
```

### Method 4: Fedora RPM (amd64 + arm64)
```bash
sudo dnf install ./ubuntu-hello-1.2.0-1.fc44.$(uname -m).rpm ./ubuntu-hello-gtk-1.2.0-1.fc44.$(uname -m).rpm
```

### Method 5: openSUSE RPM (amd64 + arm64)
```bash
sudo zypper install ./ubuntu-hello-1.2.0-1.lp160.$(uname -m).rpm ./ubuntu-hello-gtk-1.2.0-1.lp160.$(uname -m).rpm
```

### Method 6: Arch Linux (amd64 only)
```bash
sudo pacman -U ubuntu-hello-1.2.0-1-x86_64.pkg.tar.zst ubuntu-hello-gtk-1.2.0-1-x86_64.pkg.tar.zst
```

### Method 7: Snap (classic, amd64 only)
```bash
sudo snap install --dangerous --classic ubuntu-hello_1.2.0_amd64.snap
sudo snap run ubuntu-hello.host-install
```

### Method 8: AppImage (installer, amd64 + arm64)
```bash
chmod +x Ubuntu-Hello-1.2.0-$(uname -m).AppImage
./Ubuntu-Hello-1.2.0-$(uname -m).AppImage --install
```

### Method 9: Flatpak (installer, amd64 only)
```bash
flatpak install --user ./com.github.ventura8.UbuntuHello-1.2.0-x86_64.flatpak && \
    flatpak run --command=ubuntu-hello-host-install com.github.ventura8.UbuntuHello
```
Approve the polkit prompt on the host-install step to install PAM and system files.
