# 🚀 Ubuntu Hello v1.1.5 Release

Welcome to the **v1.1.5** release of **Ubuntu Hello**! This is a bugfix release for the setup wizard's webcam-testing step, which could get stuck (or, on some hardware, crash outright) with no feedback and no way to proceed — this release fixes seven distinct bugs found along the way, with the deprecated `resize-mode="immediate"` property in `onboarding.glade` being the one actually responsible for the invisible device list.

---

## ✨ Key Fixes in v1.1.5

*   **🐛 Setup wizard stuck on "Testing your webcams, please wait..."**:
    *   `scan_cameras_thread()` probed each detected `/dev/v4l/by-path` device sequentially with two unbounded blocking calls: a `udevadm` subprocess and `cv2.VideoCapture(...).read()`. Neither had a timeout, and the `cv2` call in particular cannot be cancelled once made — a single misbehaving driver (a known real-world V4L2/GStreamer failure mode on some webcam models) could freeze the whole scan forever, since results are only reported once every device finishes.
    *   Fixed: `udevadm` now has an explicit 5s timeout. The `VideoCapture` open+read runs on a watchdog thread with a 5s join; if it doesn't return in time, that device is reported as unopenable and the scan moves on instead of hanging.
*   **🐛 Live camera preview opening the wrong path**:
    *   `open_camera_for_preview()` — the live preview shown while picking a webcam — was opening the raw `/dev/v4l/by-path/...` symlink directly instead of resolving it to the real `/dev/videoN` device first. This was a regression from a later preview-thread rewrite that dropped the `os.path.realpath()` call still present in v1.1.2 and in the other two camera-opening call sites in the same file.
    *   Opening via the unresolved symlink can make certain V4L2/GStreamer driver+kernel combinations bind the wrong (or no) underlying node, leaving the preview's read loop spinning on failed reads forever with no frame and no error — indistinguishable from a hang.
    *   Fixed: restored the `os.path.realpath()` resolution, matching v1.1.2's behavior and the sibling call sites (`scan_cameras_thread`, `execute_slide3`).
*   **🐛 Uncaught crash right after the scan finishes**:
    *   `on_camera_selection_changed()` referenced `self.slide2_preview_image`, an attribute that is **never defined anywhere** in the class — a regression that does not exist in v1.1.2. This signal handler fires on every camera selection, including the automatic first-row selection that happens immediately after "Testing your webcams" completes, so it threw an uncaught `AttributeError` on essentially every run and silently killed the preview right at that point — one of several distinct causes behind the wizard appearing permanently stuck on the webcam-testing step.
    *   The unit test suite never caught this because it runs against a mocked `Gtk.Window` that auto-vivifies any missing attribute (returns a fresh mock) instead of raising like a real Python object would.
    *   Fixed: reset `self.preview_image` to the correct slide-2 widget (`self.builder.get_object("preview_image")`), matching the pattern already used in `__init__` and the fallback preview-start path.
*   **🐛 Device list vanishing after a successful scan**:
    *   `update_camera_list_gui()` builds the camera list's `ScrolledWindow` at runtime with no minimum content height. Without one, GTK could allocate it essentially zero size (GTK logs `Negative content width/height` warnings when this happens), so the whole device list silently disappeared even though the scan had succeeded and the Next button was already enabled — visually indistinguishable from the wizard being stuck.
    *   v1.1.2 called `set_min_content_height(100)` on this widget; a later rewrite dropped it.
    *   Fixed: restored `set_min_content_height(100)`, matching v1.1.2.
*   **🐛 Crash (SIGSEGV) on "Testing your webcams"**:
    *   Confirmed from a real terminal run, not a synthetic reproduction: the wizard segfaulted right after two GTK warnings — `gtk_widget_size_allocate(): attempt to allocate widget with width 0 and height -15` followed by `Negative content width/height ... GtkScrolledWindow`.
    *   Root cause: the device list's `CellRendererText` lost its `ellipsize` property in the same rewrite that dropped `set_min_content_height`. Device names/paths can be arbitrarily long (full udev product strings, `/dev/v4l/by-path/...` paths), and the list's `ScrolledWindow` disables horizontal scrolling (`PolicyType.NEVER`). Without ellipsizing, the resulting unbounded `TreeViewColumn` width request against a fixed-width parent drove GTK's layout code to a negative allocation and crashed.
    *   Fixed: restored `cell.set_property("ellipsize", Pango.EllipsizeMode.END)`, matching v1.1.2.
*   **🐛 The real root cause: the device list stayed invisible even with no crash** (`onboarding.glade`):
    *   With the crash fixed, the device list still didn't render — `Next` was enabled, the scan completed, but nothing appeared below the preview box.
    *   Root cause: `slidecontainer` had the deprecated GtkBox `resize-mode="immediate"` property set. Isolated and reproduced in a minimal standalone test: with this property set, any widget added at runtime to an already-realized/visible descendant box — exactly what `update_camera_list_gui()` does to `devicelistbox` once the scan finishes — permanently collapses to a 1×1 allocation, no matter how many further `queue_resize()` calls follow. With the default resize mode, the identical code sizes correctly.
    *   Fixed: removed the `resize-mode="immediate"` property.
*   **🐛 Live preview always black, even for a working camera**:
    *   With the device list finally rendering, the auto-selected camera showed as "Yes, compatible infrared camera" — meaning the scan itself had successfully captured and analyzed a frame — but the live preview box stayed solid black.
    *   Root cause: `update_preview_image_widget()` decodes each captured frame via `GdkPixbuf` (aliased `pixbuf`), but that alias was only ever imported *locally* inside the sibling method `open_camera_for_preview()` — never at module scope. Every call to `update_preview_image_widget()` raised `NameError: name 'pixbuf' is not defined`, silently swallowed by a bare `except: pass`. Confirmed with temporary debug logging: frames were captured and PNG-encoded correctly on every iteration, but every single widget update failed with this `NameError`.
    *   Fixed: added `from gi.repository import GdkPixbuf as pixbuf` at module level.
*   **🧪 Verified against real hardware and real terminal runs**, not just mocks: an actual `ubuntu-hello-gtk --force-onboarding` run from a terminal reproduced the segfault above before the crash fix; after it, the same run completes with no GTK warnings and no crash. After the `resize-mode` fix, the user confirmed the device list renders normally, showing real per-camera results (two "Yes, compatible infrared camera" entries auto-selected and highlighted on their hardware). Debug logging then pinpointed the `NameError` behind the still-black preview; after the fix, frames decode and display correctly. Also confirmed the `AttributeError` traceback from the earlier fix stays gone. Added regression tests: one simulating a device whose `read()` never returns (asserts the scan reports it unopenable via the timeout path), and one asserting `on_camera_selection_changed` sets `preview_image` to the correct widget rather than a nonexistent attribute.

## 📥 Installation

Download assets from the [GitHub Release](https://github.com/ventura8/ubuntu-hello/releases/tag/v1.1.5) page. Verify against `SHA256SUMS` before installing.

### Method 1: Quick Install (from release tag)
Download and review [`install.sh`](https://github.com/ventura8/ubuntu-hello/blob/v1.1.5/install.sh) from the **v1.1.5** tag, then run `bash install.sh` locally.

### Method 2: PPA (Ubuntu / Linux Mint)
```bash
sudo add-apt-repository ppa:ventura8/ubuntu-hello
sudo apt update
sudo apt install ubuntu-hello
```

### Method 3: Debian `.deb` (amd64 + arm64)
```bash
sudo apt install ./ubuntu-hello_1.1.5-1ppa1_$(dpkg --print-architecture).deb ./ubuntu-hello-gtk_1.1.5-1ppa1_$(dpkg --print-architecture).deb
```

### Method 4: Fedora RPM (amd64 + arm64)
```bash
sudo dnf install ./ubuntu-hello-1.1.5-1.fc44.$(uname -m).rpm ./ubuntu-hello-gtk-1.1.5-1.fc44.$(uname -m).rpm
```

### Method 5: openSUSE RPM (amd64 + arm64)
```bash
sudo zypper install ./ubuntu-hello-1.1.5-1.lp160.$(uname -m).rpm ./ubuntu-hello-gtk-1.1.5-1.lp160.$(uname -m).rpm
```

### Method 6: Arch Linux (amd64 only)
```bash
sudo pacman -U ubuntu-hello-1.1.5-1-x86_64.pkg.tar.zst ubuntu-hello-gtk-1.1.5-1-x86_64.pkg.tar.zst
```

### Method 7: Snap (classic, amd64 only)
```bash
sudo snap install --dangerous --classic ubuntu-hello_1.1.5_amd64.snap
sudo snap run ubuntu-hello.host-install
```

### Method 8: AppImage (installer, amd64 + arm64)
```bash
chmod +x Ubuntu-Hello-1.1.5-$(uname -m).AppImage
./Ubuntu-Hello-1.1.5-$(uname -m).AppImage --install
```

### Method 9: Flatpak (installer, amd64 only)
```bash
flatpak install --user ./com.github.ventura8.UbuntuHello-1.1.5-x86_64.flatpak && \
    flatpak run --command=ubuntu-hello-host-install com.github.ventura8.UbuntuHello && \
    flatpak run com.github.ventura8.UbuntuHello
```
Approve the polkit prompt on the host-install step to install PAM and system files.

## 📋 Changelog (v1.1.5)

*   **Release**: Version **`1.1.5`** / **`v1.1.5`** from repo-root **`VERSION`**; `debian/changelog` top entry added.
*   **Fix**: setup wizard camera scan (`scan_cameras_thread`) no longer freezes forever on an unresponsive device — `udevadm` and `cv2.VideoCapture` calls now have explicit timeouts.
*   **Fix**: live camera preview (`open_camera_for_preview`) restored to resolving `/dev/v4l/by-path/...` symlinks to their real `/dev/videoN` device before opening, matching v1.1.2 and the sibling call sites — regression from a later preview-thread rewrite.
*   **Fix**: `on_camera_selection_changed` referenced a nonexistent `self.slide2_preview_image` attribute, throwing an uncaught `AttributeError` on every camera selection and silently breaking the preview right after the scan completes. Fixed to reset `preview_image` to the correct widget via `self.builder.get_object("preview_image")`.
*   **Fix**: `update_camera_list_gui`'s dynamically-built `ScrolledWindow` now sets `set_min_content_height(100)` again, matching v1.1.2 — without it GTK could allocate the device list ~0 size and it would silently vanish after a successful scan.
*   **Fix (crash)**: restored `ellipsize` on the device list's `CellRendererText`; without it, long device names/paths against a non-horizontally-scrolling `ScrolledWindow` drove GTK to a negative widget allocation and a SIGSEGV, confirmed from a real terminal run of the installed binary.
*   **Fix (root cause, `onboarding.glade`)**: removed the deprecated `resize-mode="immediate"` property from `slidecontainer`. It permanently collapses any widget added at runtime to an already-visible descendant box to a 1×1 allocation; confirmed the device list renders correctly on real hardware after removing it.
*   **Fix (black preview)**: `GdkPixbuf` (aliased `pixbuf`) was only imported locally in `open_camera_for_preview()`, not at module scope, so the sibling `update_preview_image_widget()` always raised `NameError` and silently never displayed a frame. Imported at module level.
*   **Fix (concurrency, found in PR review)**: the scan watchdog's `open_result`/`abandoned` state was captured by the worker closure by reference instead of bound per loop iteration, so a worker that finished late could corrupt a *later* device's result; separately, the timeout handoff between the main thread and the worker wasn't atomic, so a capture could be silently discarded unreleased. Rewritten so each iteration owns a private `state`/`lock` pair with an atomic completion/timeout handoff. The timeout is now the module-level `CAMERA_PROBE_TIMEOUT` constant so tests exercise the real watchdog path instead of faking `Thread.is_alive()`.
*   **Tests**: added a regression test simulating a hanging camera device (now via a genuinely blocked `threading.Event`, not a faked `is_alive()`), a test asserting `on_camera_selection_changed` sets `preview_image` to the correct widget object, and a test confirming a late-finishing timed-out device cannot corrupt a subsequent device's scan result; full `tests/test_onboarding.py` suite (60 tests) passes.
