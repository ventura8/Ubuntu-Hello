# Ubuntu Hello v1.2.8 - Keyring Repair

This release adds a one-click repair for a login keyring that stopped accepting your password, and detects the problem in Settings.

---

## 🔧 What's in this release

*   **🔑 Repair a login keyring that stopped unlocking.** A login keyring can get damaged, or its password can drift away from your login password (seen after another app wrote to the keyring while it was open). Face login still works, but the keyring then rejects every password: the one Ubuntu Hello hands over and the one you type. Until now that failed silently and left you with keyring prompts. New **`sudo ubuntu-hello keyring repair`** stores your current password first, then renames the old `login.keyring` to `login.keyring.broken-<date>` (kept, never deleted). Your next login creates a fresh keyring that unlocks automatically. Passwords saved in the old keyring need to be entered again. GNOME Keyring only; KWallet users are pointed to System Settings.
*   **⚠️ Settings detects it for you.** When auto-unlock is on and your login keyring is still locked in your running session, the **Keyring** tab shows a warning and a **Repair Keyring** button that runs the same repair after checking your password.
*   **📖 Troubleshooting.** The README explains how to tell a broken keyring from a face-login problem: if your typed password is rejected too, the keyring is the cause.
*   **🧹 Code quality.** Clears the SonarCloud findings in the PAM helper wait loop. The signal-retry logic is now one small function, and a new test interrupts a real wait with a signal to prove it retries.

Nine new translatable strings, translated in all 98 languages. No new config keys.

## 📥 Installation (from Release assets)

Verify downloads against `SHA256SUMS` on the Release page before installing. Download this release's assets into an empty/clean directory before running these commands — the wildcards below match by filename pattern, and leftover assets from another version in the same directory can make a package manager see multiple matches (or, for the AppImage command, pass a second matched file as a stray argument).

| Format | Command |
|--------|---------|
| **Debian** (amd64 + arm64) | `sudo apt install ./ubuntu-hello_*_$(dpkg --print-architecture).deb ./ubuntu-hello-gtk_*_$(dpkg --print-architecture).deb` |
| **Fedora** (amd64 + arm64) | `sudo dnf install ./ubuntu-hello-[0-9]*fc44*.$(uname -m).rpm ./ubuntu-hello-gtk-*fc44*.$(uname -m).rpm` |
| **openSUSE** (amd64 + arm64) | `sudo zypper install ./ubuntu-hello-[0-9]*lp160*.$(uname -m).rpm ./ubuntu-hello-gtk-*lp160*.$(uname -m).rpm` |
| **AppImage** (amd64 + arm64) | `chmod +x Ubuntu-Hello-*-$(uname -m).AppImage && ./Ubuntu-Hello-*-$(uname -m).AppImage --install` |
| **Arch** (amd64 only) | `sudo pacman -U ./ubuntu-hello-[0-9]*.pkg.tar.zst ./ubuntu-hello-gtk-*.pkg.tar.zst` |
| **Snap** (amd64 only) | `sudo snap install --dangerous --classic ubuntu-hello_*_amd64.snap && sudo snap run ubuntu-hello.host-install` |
| **Flatpak** (amd64 only) | `flatpak install --user ./com.github.ventura8.UbuntuHello-*.flatpak && flatpak run --command=ubuntu-hello-host-install com.github.ventura8.UbuntuHello` |

PPA (Ubuntu 22.04, 24.04 and 26.04). **On 22.04 use the PPA**: the `.deb` assets above are built on 26.04:

```bash
sudo add-apt-repository ppa:ventura8/ubuntu-hello && sudo apt update && sudo apt install ubuntu-hello
```

Optional source install: download [`install.sh`](https://github.com/ventura8/ubuntu-hello/blob/v1.2.8/install.sh) from the **v1.2.8** tag, review it, then run locally — do not pipe a moving branch URL directly to `bash`.
